# Lessons learned

Every process correction gets a line here (same PR as the correction, or a docs task). Incidents are tracked as issues with topic `process`; open measures are tasks reviewed by the product owner.

| Date | Problem | Cause | Measure | Status |
|---|---|---|---|---|
| 2026-11-05 | Reviews started from the Lead's long session, with the same context every time (#31) | no artifact between the PR and the review; every round read everything again | `tools/review-pack.py` prints task, why, out of scope, CI, earlier findings, round, scope drift and matching lessons from the API; the Lead reviews it in a fresh read-only checker session | done |
| 2026-11-05 | The product owner reviewed PRs without a guide | the PR text described the change, not where the risk is | org PR template asks for the *Reviewer guide* – what and why, design decisions, risky spots, where to start; the developer fills it in | done |
| 2026-11-05 | Text from issues and PRs could steer the agent that reviews it | instructions and data arrive in one context, and nothing filtered the text | review pack fences issue/PR text, strips HTML comments and invisible Unicode and caps the length; the skills get an *Untrusted input* section (Lead, after the merge) | open: skills |
| 2026-11-05 | `tools/install.sh` reported six `copied` for an install into a nested path nobody reads (#29) | default profiles root derived from `HERMES_HOME`, which is the profile directory inside the agent runtime | default is `$HERMES_HOME/profiles` or `~/.hermes/profiles`; a profile-shaped `HERMES_HOME` is refused with a hint to `--profiles-root` | done |
| 2026-11-05 | Sprint stalled: a decision in a comment did not reach the Lead (#24) | github-watch read states, not comments | Assignee = inbox: comments and manual assignments of the product owner are reported; manual assignment wins over the sync | done |

| 2026-11-06 | BookKeeper#41 sat on Action for 40 minutes with no developer job and blocked `dev-1` (#57) | the dispatcher set Action before the start was complete; assigning failed because the Lead bot could only read the repository | write access of both bots is checked before a start; Action only together with the job, a failed start goes back to Goal; an Action card without PR and job for 15 min goes to the product owner and frees its instance | done, verify on the next start |
| 2026-11-07 | A tick took 8–10 s, the window in which Hermes drops further webhook triggers | dispatcher, watch and sync made six GitHub reads one after another (~0.5–1.8 s each), three of them full board reads | watch reads PRs, issues, board and merged PRs in parallel, the sync runs alongside; dispatcher stays first because its starts change the state | done, ~4 s per tick |

| 2026-11-07 | The tick's Lead message held the job for a whole Lead turn, and Hermes dropped every trigger in that time | Hermes delivers to Bot Chat synchronously inside the job run, and refuses a trigger while the job is in flight | local Hermes patch (`hermes-config/patches`): async Bot Chat delivery through the existing pending lane, woken by the existing delivery-queue watch, and `cron_job_on_busy: coalesce`; our own filter script and timestamp logic removed in favour of the route's declarative filters | done, feature request drafted |
| 2026-11-07 | Loop rules spread over three scripts, the project workflows and a bash/Python mix; the board was read six times per tick | grown step by step, each fix where it was needed | loop engine `tools/loop`: one read per scope, pure rule functions with table tests, one write layer; the project workflows and the old crons are switched off | done, the old scripts stay as the way back |
